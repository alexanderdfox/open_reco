A Clean-Room Video Recommendation Algorithm

An Independent Two-Stage System Inspired by Public Descriptions of Large-Scale Recommenders
Clean-Room Design
November 2026  ·  Educational / Research Prototype
Abstract

We present a complete, independently designed video recommendation algorithm that follows the publicly known two-stage architecture used by major video platforms: candidate generation followed by ranking. The system is constructed exclusively from open techniques and the high-level descriptions published by platform operators. No proprietary code, model weights, or internal documentation is used. The resulting algorithm is therefore free of intellectual-property contamination and suitable for educational, research, or commercial clean-room implementations.

1. Introduction

Large-scale video recommendation systems typically employ a two-stage pipeline. The first stage (candidate generation) retrieves a few hundred items from a corpus of millions or billions with high recall. The second stage (ranking) scores those candidates with high precision and returns a short ordered list. This design has been publicly described in research papers and platform documentation since at least 2016.

The algorithm below is a clean-room reconstruction of that architecture. All components—feature construction, retrieval, scoring, and feedback—are original implementations based solely on publicly available knowledge.

2. System Architecture

Let $\mathcal{U}$ be the set of users and $\mathcal{V}$ the set of videos. Given a user $u \in \mathcal{U}$, the system returns an ordered list of $n$ videos:

$$ \mathrm{Recommend}(u, n) = \mathrm{Top}\text{-}n\bigl(\mathrm{Rank}\bigl(\mathrm{Candidates}(u)\bigr)\bigr) $$

2.1 Candidate Generation

The candidate generator produces a set $C_u \subset \mathcal{V}$ of size roughly 200–600. Three complementary strategies are combined:

  1. Embedding retrieval. Users and videos are mapped into a shared $d$-dimensional space. Videos nearest to the user embedding (cosine similarity) are retrieved.
  2. Collaborative filtering. Videos co-watched by users with overlapping history are promoted.
  3. Popularity prior. A small fraction of globally popular items is mixed in to support exploration and cold-start users.

Already-watched videos are removed from $C_u$.

2.2 Ranking

Each candidate $v \in C_u$ receives a scalar score $s(u,v)$. The current implementation uses a transparent linear combination:

$$ s(u,v) = \alpha \cdot \mathrm{sim}(e_u, e_v) + \beta \cdot \mathrm{retention}(v) + \gamma \cdot \mathrm{popularity}(v) $$

where $e_u$ and $e_v$ are the user and video embeddings, $\mathrm{sim}$ is cosine similarity, and $\alpha+\beta+\gamma=1$. The ranked list is obtained by sorting candidates in descending order of $s(u,v)$.

3. Feature Construction

3.1 Video Embedding

A simple bag-of-tags embedding is used. For a video $v$ with tag set $T_v$:

$$ e_v[i] = \frac{1}{\| \tilde{e}_v \|_2} \sum_{t \in T_v} \mathbf{1}_{\{h(t) \bmod d = i\}} $$

where $h$ is a hash function and $d$ is the embedding dimension (default 32). The vector is $\ell_2$-normalized.

3.2 User Embedding

The user embedding is a watch-time-weighted average of the embeddings of previously watched videos:

$$ e_u = \frac{1}{Z} \sum_{(v,w) \in H_u} w \cdot e_v, \qquad Z = \sum_{(v,w) \in H_u} w $$

where $H_u$ is the user’s recent watch history and $w$ is the observed watch duration in seconds. The result is again $\ell_2$-normalized.

4. Formal Algorithm

Algorithm Recommend(u, n)
Input:  user u, desired list length n
Output: ordered list of n video identifiers

1:  Hu ← watch history of u
2:  eu ← UserEmbedding(Hu)
3:
4:  // Candidate Generation
5:  C ← ∅
6:  C ← C ∪ NearestNeighbors(eu, k=400)          // embedding retrieval
7:  C ← C ∪ CoWatchCandidates(u, k=200)            // collaborative
8:  C ← C ∪ PopularitySample(k=100)                // exploration
9:  C ← C \ {v | v already watched by u}
10:
11: // Ranking
12: for each v ∈ C do
13:     ev ← VideoEmbedding(v)
14:     sim ← cosine(eu, ev)
15:     ret ← average watch fraction of v
16:     pop ← log(1 + view_count(v))
17:     s(v) ← 0.55·sim + 0.25·ret + 0.20·pop
18: end for
19:
20: return Top-n videos ordered by descending s(v)

5. Feedback Loop

Every interaction (watch, like, “not interested”) updates two structures:

  • the user’s watch history $H_u$ (rolling window),
  • the video’s aggregate statistics (view count and total watch time).

These updates immediately affect future candidate generation and ranking for that user and for collaborative signals.

6. Implementation Notes

A complete reference implementation is provided in Rust. The design is deliberately modular:

Component File Responsibility
Data models models.rs User, Video, Interaction structures
Features features.rs Embedding construction & cosine similarity
Candidates candidate.rs High-recall retrieval strategies
Ranking ranking.rs Scoring function
Engine engine.rs Orchestration & public API

The linear ranking function can be replaced by any supervised model (gradient boosting, neural network, etc.) without altering the rest of the pipeline.

7. Clean-Room Statement

This algorithm was designed solely from:

  • public platform documentation describing recommendation goals and high-level signals,
  • the 2016 research paper that first publicly outlined a two-stage deep recommendation architecture for video,
  • standard techniques from the open recommender-systems literature (collaborative filtering, embedding retrieval, multi-stage ranking).

No proprietary source code, model checkpoints, internal feature lists, or non-public documentation were examined or reproduced. The implementation is therefore an independent creation suitable for clean-room development.
